Issues & Fixes

[High] Privilege-wall enforcement was reactive, not built into first-draft generation.
What: The initial timeline draft included legal-strategy substance (e.g., "TRO viability," "do not confront") sourced from privileged emails E011/E012, requiring a manual correction pass before the HTML was generated.
Impact: Had this correction pass been skipped, privileged attorney work product would have leaked into a redistributable report — a direct Authorization-law violation.
Fix: Add an explicit sub-step to "Build Timeline of Events" requiring that any event sourced solely from a privileged document be rendered as date/topic metadata only (never advice content), enforced by an automated keyword/source-tag check before Verify is marked passed, not only at Synthesize.
[Medium] Document-type taxonomy doesn't cover forensic/expert-exhibit materials.
What: D003 (forensic report) and D005 (comparative technical exhibit) don't map cleanly onto EMAIL/CONTRACT/MEMO/CORRESPONDENCE/DEPOSITION, forcing "Needs Review" confidence and a MEMO-adjacent workaround.
Impact: Two of six PDF exhibits (33%) required non-standard categorization, adding manual-review burden and reducing the rubric engine's "same input, same result" determinism for this common evidence type.
Fix: Add an EXPERT/FORENSIC-REPORT type to the rubric engine with its own checklist (examiner identity, methodology, chain of custody, findings) so future matters with forensic or expert exhibits get a Confident classification instead of defaulting to Needs Review.
[Medium] Exit-interview / witness-statement documents also lack a clean taxonomy fit.
What: D006 (Exit Interview Form) was classified CORRESPONDENCE with Needs Review confidence since it is witness-statement-like but not a sworn DEPOSITION.
Impact: Similar friction to the forensic-report gap; likely to recur in most employment-related trade-secret matters.
Fix: Add a WITNESS STATEMENT/INTERVIEW type distinct from DEPOSITION for non-sworn but material witness accounts.
[Low] Content-integrity/prompt-injection scanning succeeded but had no automated block.
What: E017 contained a live prompt-injection payload attempting to suppress Kestrel-related findings; it was correctly detected and ignored, but detection relied on the analyst's manual read-through rather than an automated pre-filter.
Impact: A less careful pass could miss embedded injection text in a routine-looking ticket-closure email.
Fix: Add an automated pre-ingestion scan (pattern match for phrases like "system override," "ignore prior instructions," "do not flag to human") that flags matches as Critical before the per-file classification step begins, independent of analyst attentiveness.

Quick Wins

  • Add an automated privileged-source keyword filter that runs before Verify on the Timeline and Contradictions activities, not just at Synthesize.
  • Extend the rubric engine with EXPERT/FORENSIC-REPORT and WITNESS STATEMENT document types to reduce Needs-Review volume (currently 5 of 25 records, 20%).
  • Automate the prompt-injection scan as a pre-ingestion gate rather than relying on manual read-through during classification.
